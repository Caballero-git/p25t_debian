#+TITLE: P25T — boot chain and SD card layout
#+DATE: 2026-09-25
#+STARTUP: overview

* The chain
  1. Boot ROM → stock *SPL on the eMMC* (the bootloader stays locked and
     untouched).
  2. The stock SPL tries the microSD first. It looks for a GPT partition
     named ~uboot~ (then ~uboot_a~, ~uboot_b~) and loads a FIT image from
     offset +0 or, if that copy is bad, from +4096 sectors.
  3. The FIT holds *mainline U-Boot v2026.10-rc5* (~generic-rk3568~ based),
     *BL31* (Rockchip ~rk3568_bl31_v1.46.elf~ from ~rkbin~, split into its 6
     load segments) and U-Boot's own DT.
  4. U-Boot's fixed ~bootcmd~ loads ~Image~, the DTB and ~initramfs.cpio.gz~
     from the FAT partition ~P25TBOOT~ (partition 4) and runs ~booti~.
  5. Linux starts ~/init~ of our initramfs (busybox), which logs to the
     card, tunes the USB PHY and hands over to Debian on ~p25troot~.

* SD card layout (512-byte sectors)
  | Sectors            | GPT name / label    | Contents                                    |
  |--------------------+---------------------+---------------------------------------------|
  | 16384–24575        | ~uboot~             | FIT at +0 and +4096                         |
  | 24576–32767        | ~uboot_a~           | same FIT                                    |
  | 32768–40959        | ~uboot_b~           | same FIT                                    |
  | 65536–589823       | ~P25TBOOT~ (FAT32)  | Image, DTB, initramfs, flags, logs          |
  | 1331200 (+32)      | outside partitions  | U-Boot status note (~env export~ text)      |
  | 2097152–end        | ~P25TROOT~ / ext4 label ~p25troot~ | Debian 13 root filesystem    |

  Files on ~P25TBOOT~:
  | File                          | Purpose                                                 |
  |-------------------------------+---------------------------------------------------------|
  | ~Image~                       | kernel (current)                                        |
  | ~rk3566-teclast-p25t.dtb~     | device tree (current) - the *active* copy, set by ~set-usb-role.sh~ |
  | ~rk3566-teclast-p25t-normal.dtb~, ~-usbhost.dtb~ | role copies (USB-C device / host), see "Choosing the USB-C role" |
  | ~initramfs.cpio.gz~           | stage-1 system                                          |
  | ~Image.pre-NNNN-backup~, ~*.dtb.pre-NNNN-backup~ | the 2 previous working kernels + DTBs, for rollback (see "Rescue and rollback") |
  | ~CARD-SHA256SUMS~             | checksums of ~Image~, the active DTB, ~initramfs.cpio.gz~, ~diag-display.sh~ (check: ~sha256sum -c CARD-SHA256SUMS~) |
  | ~boot-debian~ (empty flag)    | present → hand over to Debian                           |
  | ~no-usb-tuning~ (empty flag)  | present → skip the USB PHY tuning                       |
  | ~autorun.sh~ (optional)       | run in background by stage 1 (experiments only)         |
  | ~logs/~                       | ~bootcount~ and ~boot-N-*.txt~ from every boot          |

* U-Boot
** Build
   Source: ~https://github.com/u-boot/u-boot.git~ tag ~v2026.10-rc5~.
   #+begin_src sh
   git clone --branch v2026.10-rc5 https://github.com/u-boot/u-boot.git
   cd u-boot
   cp ../p25t-linux/u-boot/p25t-u-boot.config .config
   make olddefconfig
   make CROSS_COMPILE=aarch64-linux-gnu- -j$(nproc)
   #+end_src
   Only ~u-boot.bin~ and ~u-boot.dtb~ are used; the FIT is made by our own
   ~p25t.its~ (the stock SPL needs the legacy Rockchip FIT layout:
   ~mkimage -E -B 0x200 -p 0x1000~).

** Boot command (literal, from the config)
   It writes a small status note to the card at every step, so a failed
   boot can be diagnosed on the PC without a serial console:
   #+begin_example
   setenv stage bootcmd-reached; <save note>
   setenv bootargs console=ttyS2,1500000n8 earlycon clk_ignore_unused loglevel=7 rdinit=/init panic=0
   fatload mmc 1:4 ${kernel_addr_r}  Image
   fatload mmc 1:4 ${fdt_addr_r}     rk3566-teclast-p25t.dtb
   fatload mmc 1:4 ${ramdisk_addr_r} initramfs.cpio.gz
   setenv stage linux-loaded; <save note>; booti ...
   on failure: stage = booti-failed / load-failed; <save note>; fastboot usb 0
   #+end_example
   ~<save note>~ = ~mmc dev 1 && env export -t 0x11000000 && mmc write 0x11000000 0x145000 0x20~
   (~0x145000~ = sector 1331200). In U-Boot, ~mmc 1~ is the microSD.

   Read the note on the PC (~<CARD-DEVICE>~ is e.g. ~/dev/sdb~):
   #+begin_example
   sudo dd if=<CARD-DEVICE> bs=512 skip=1331200 count=32 status=none | tr -d '\0' | grep stage
   #+end_example

** FIT and the SD image
   #+begin_src sh
   bash u-boot/build_sd_image.sh ~/src/u-boot rkbin/bin/rk35/rk3568_bl31_v1.46.elf \
        linux/arch/arm64/boot/Image \
        linux/arch/arm64/boot/dts/rockchip/rk3566-teclast-p25t.dtb \
        initramfs.cpio.gz p25t-sd.img
   #+end_src
   - ~split_bl31.py~ cuts the BL31 ELF into its load segments
     (~bl31_0x...bin~) referenced by ~p25t.its~.
   - The FIT must stay below 2 MiB (the partitions hold two copies).
   - Output is reproducible except for the FIT timestamp (3 bytes).

   Write the image with the checking writer (refuses non-removable disks,
   asks for ~YES~, verifies afterwards):
   #+begin_example
   sudo bash tools/write_sdcard.sh p25t-sd.img <CARD-DEVICE>
   #+end_example

* Stage 1: the initramfs (~initramfs/init~)
  In order:
  1. Mounts ~proc~, ~sys~, ~devtmpfs~, ~configfs~; mounts ~P25TBOOT~ on ~/boot~.
  2. Increments ~logs/bootcount~ → N, writes ~logs/boot-N-dmesg.txt~ and
     ~boot-N-status.txt~.
  3. USB2 PHY tuning (stock values, see [[file:hardware.org][hardware]]); before/after
     in ~boot-N-usbphy.txt~. Skipped if ~/boot/no-usb-tuning~ exists.
  4. *Hand-over to Debian* if ~/boot/boot-debian~ exists:
     - reads SARADC channel 0; raw < 900 means a volume key is held →
       stay in stage 1 (rescue);
     - ~findfs LABEL=p25troot~, mount it read-only, check ~/sbin/init~;
     - move ~/dev~, ~/proc~, ~/sys~ and ~exec switch_root /newroot /sbin/init~.
     - Result in ~boot-N-handover.txt~.
  5. If it stays: read-only PMIC and GPIO dumps, a hello on ~tty1~,
     optional ~autorun.sh~, USB gadget (ACM serial + NCM network,
     ~1d6b:0104~, retried up to 5 times), ~usb0~ = 192.168.7.2, ~telnetd~,
     shell on ~/dev/ttyGS0~, periodic snapshots.

  The cpio holds only a static arm64 *busybox 1.37.0* (~defconfig~ plus
  ~CONFIG_STATIC=y~; ~devmem~, ~i2c*~, ~findfs~, ~switch_root~ are all
  busybox applets) and our ~init~. Rebuild it:
  #+begin_example
  cd busybox && make defconfig && sed -i 's/^# CONFIG_STATIC is not set/CONFIG_STATIC=y/' .config
  make CROSS_COMPILE=aarch64-linux-gnu- -j$(nproc)
  make CROSS_COMPILE=aarch64-linux-gnu- CONFIG_PREFIX=<INITRAMFS-DIR> install
  mkdir -p <INITRAMFS-DIR>/{boot,dev,etc,proc,sys,tmp}
  install -m 755 p25t-linux/initramfs/init <INITRAMFS-DIR>/init
  cd <INITRAMFS-DIR> && find . | cpio -o -H newc -R 0:0 | gzip -9 > ../initramfs.cpio.gz
  #+end_example
  The card currently carries the build with sha256 ~ac4f3d83e704…~; its
  ~init~ is byte-identical to ~initramfs/init~ in this folder.

* Choosing the USB-C role for the next boot
  U-Boot's ~bootcmd~ hardcodes the DTB filename it loads
  (~rk3566-teclast-p25t.dtb~, see "Boot command" above), so the USB-C
  port's role (~dr_mode~ - device/peripheral vs. host, fixed at kernel
  probe time) can't change after the kernel has booted - it can only be
  chosen for the boot that hasn't happened yet, by deciding which DTB
  variant's *content* sits at that exact filename.

  ~tools/set-usb-role.sh~ does exactly that. It lives in the tablet's home
  directory (copied there with ~scp~, not installed as a command) and runs
  on the tablet itself - ~P25TBOOT~ is mounted at ~/boot/firmware~, see
  debian.org. Run it without ~sudo~; it calls ~sudo~ itself:
  #+begin_example
  bash ~/set-usb-role.sh host    # next boot: USB-C as host (wired keyboard/mouse)
  bash ~/set-usb-role.sh normal  # next boot: USB-C as device (console/network - default)
  bash ~/set-usb-role.sh status  # which one is currently set
  #+end_example
  Since 2026-09-29, ~host~ and ~normal~ also update the
  ~rk3566-teclast-p25t.dtb~ line in ~CARD-SHA256SUMS~ and re-check every
  entry (~sha256sum -c~), stopping with an error if anything fails.

  *The role copies must be refreshed on every DT change.* The script copies
  whatever ~-normal.dtb~ / ~-usbhost.dtb~ contain. On 2026-09-29 both
  predated patch 0017, so a role switch silently put back a DT without
  the touchscreen node - and a checksum list that no longer matched. So
  a DT deploy is: copy the new ~rk3566-teclast-p25t.dtb~ build to
  ~-normal.dtb~ and ~-usbhost.dtb~ build to ~-usbhost.dtb~, then run the
  script for the wanted role (check ~status~ *before* replacing the role
  copies - afterwards the active DTB matches neither).
  It copies either ~rk3566-teclast-p25t-usbhost.dtb~ or the permanent
  ~rk3566-teclast-p25t-normal.dtb~ (a copy of the working "normal" DTB
  kept under its own name specifically so the rollback-backup pruning
  described under patch 0015 in kernel.org never touches it) over the
  active ~rk3566-teclast-p25t.dtb~, then leaves the actual ~reboot~ to
  the user. In host mode the port also sources power for whatever's
  plugged in rather than only receiving it, so charging behaviour over
  that same cable may differ - this exact host-mode DTB was already
  hardware-confirmed working with a USB wireless keyboard/mouse receiver
  early in the project (patches 0007+0008), so the mode itself is
  known-good; only the convenience of switching to it is new here. Wi-Fi
  (and SSH over it) is unaffected either way - it's a separate
  controller from the USB-C PHY.

* Rescue and rollback
  | Situation                           | Action                                                              |
  |-------------------------------------+---------------------------------------------------------------------|
  | Debian does not come up             | hold a volume key while powering on → stage-1 shell over USB        |
  | New kernel does not boot            | on the PC, copy the newest ~Image.pre-NNNN-backup~ over ~Image~ and its ~*.dtb.pre-NNNN-backup~ over ~rk3566-teclast-p25t.dtb~ |
  | Want Android back                   | power off, remove the card                                          |
  | Nothing boots at all                | read the status note (above) and ~logs/~ on the PC                  |

  Backup rule (since 2026-10-01): ~P25TBOOT~ (253 MB) keeps the running
  kernel plus the *2 previous working* kernels, each as
  ~Image.pre-NNNN-backup~ with its DTB(s), where NNNN is the first patch
  the newer kernel added. A deploy first copies the outgoing ~Image~ and
  active DTB to ~/home/jose/boot-backups/~ on ~p25troot~ (ext4, plenty of
  space, readable from the PC); older backups go to
  ~/home/jose/boot-backups/old/~. Before a deploy, check ~df -h
  /boot/firmware~: a new ~Image~ is ~33 MB.
  State 2026-10-01: ~Image~ (patches up to 0022), ~Image.pre-0021-backup~
  (0020), ~Image.pre-touch-fw-backup~ (0019). Note:
  ~rk3566-teclast-p25t.dtb.pre-0021-backup~ is the *host-mode* DTB of
  0020 (~b5246dbb…~; the tablet was in host mode at that deploy) - a
  rollback with it boots with USB-C as host (Wi-Fi/SSH unaffected). The
  normal-mode DTB of 0020 (~14815f26…~) is not kept; rebuild it from the
  git tree at patch 0020 if needed. Lesson: back up both role copies.
